# Personal Finance Tool — Build Plan & AI Prompts

## How to use this with free AI agents

You build the app in 10 small prompts, each one a fresh chat, each one checked with a single command before you move on. The project's rules live in one file (`docs/SPEC.md`, below), so prompts stay short and every agent — Copilot, Gemini, ChatGPT — works from the same contract.

**Recommended tool:** VS Code + GitHub Copilot Free in **Agent mode** (it can read and write files in your project). Use Gemini CLI / Gemini Code Assist free as a backup when Copilot's monthly quota runs out. Use ChatGPT/Gemini web chat only for debugging single errors.

**Rules that save usage**

1. One prompt = one new chat. Old chat history burns tokens and confuses the model.
2. Always attach `docs/SPEC.md` plus only the files the prompt lists (in Copilot: type `#file:docs/SPEC.md`). In a web chat, paste SPEC.md above the prompt.
3. Copy each prompt exactly. They already tell the agent: no explanations, full files only, don't touch other files.
4. Run the **Check** command after every prompt. Only move on when it passes.
5. If it fails, use the Fix prompt (last section) in a new chat with the error text — don't re-run the whole prompt.
6. Commit after every passing step (`git add -A && git commit -m "step N"`), so a bad AI answer can be undone with `git checkout .`.
7. Never paste your real bank statement into a cloud AI. Prompt 3 builds a fake statement in the same format for testing; your real file stays on your PC.

## What the Xac Bank statement looks like

The sample (one month, about 130 transaction rows) is one sheet, `AccountStatement`, where **every cell is text** — dates, amounts and balances included. The parser must convert them itself.

**Layout**

| Rows | Content | How to read it |
| --- | --- | --- |
| 1–8 | Header block: label in column A, value in column B; totals in F/G | Holder = B3, account no. = B5, currency = B7, period start/end = G6/G7 |
| 9 | Column headers (Mongolian) | Find this row by searching for `Огноо`, don't hard-code row 9 |
| next row | `Эхний үлдэгдэл` (opening balance) | Store as import metadata, not a transaction |
| data rows | One transaction per row | See columns below |
| last data row | `Эцсийн үлдэгдэл` (closing balance) | Stop here; ignore `Хэвлэсэн` footer rows |

**Columns**

| Col | Header | Meaning | Example |
| --- | --- | --- | --- |
| A | Огноо | Date `YYYY-MM-DD` | 2026-09-14 |
| B | Гүйлгээний утга | Description | `13174691 UB 400000**0000 CU-334 LENIN CLUB` |
| C | Харьцсан данс | Counterparty / account | `УЛААНБААТАР СМАРТ КАРТ ГОЛОМТ БАНК-8115105694` |
| D | Гүйлгээний дугаар | Bank reference — unique, used to skip duplicates | SX0000000 |
| E | Орлого | Income, `-` when empty | 100,000.00 |
| F | Зарлага | Expense, `-` when empty | 4,750.00 |
| G | Үлдэгдэл | Running balance | 250,000.00 |

**Transaction types found**

| Type | How to recognise it | Merchant / counterparty to extract |
| --- | --- | --- |
| Card POS | Description matches `<terminal> <city> 400000**0000 <MERCHANT>` | Text after the masked card number, e.g. `CU-334 LENIN CLUB` |
| QPay | Description starts with `qpay` (any case) | Column C minus the trailing bank name and account digits, e.g. `АЗИ БРЮ ХАУС ХХК` |
| Transfer in/out | Anything else with a person or company in column C | Column C name, e.g. `ДОРЖ БАТ` |
| Own-account transfer | Column C ends with one of *your* account numbers (here 5000000002 and 100000000003) | Mark as transfer — not income, not expense |
| Bank fee | `XACINFO ҮЙЛЧИЛГЭЭНИЙ ШИМТГЭЛ` (50₮ after almost every transaction), `Банк хоорондын шилжүүлгийн шимтгэл` (200₮), QPay `TRX:` charge to `ККТТ ХХК` | None — auto-classified |

Two things the tool must handle: about half the rows are 50₮ XACINFO fees, so they should be auto-classified and hidden from the review screen; and the same shop appears with different branch numbers (`CU-334`, `CU-192`, `CU-224`), so rules need *contains/starts-with* matching, not only exact names.

## Architecture

A local Streamlit web app (opens in your browser at `localhost:8501`) on top of a local PostgreSQL database. No server, no login, one user. Streamlit is chosen because it is pure Python, needs no HTML/JS, and free AI agents write it reliably.

**Stack:** Python 3.12 · PostgreSQL 16 · SQLAlchemy 2 (Core, with `text()` SQL) + psycopg 3 · pandas + openpyxl · Streamlit · python-dotenv · pytest.

**Data flow on each upload**

1. Upload `.xlsx` on the Upload page → file hash checked, so the same file can't be imported twice.
2. Parser registry picks the bank parser (Xac now; Khan, Golomt, TDB later) → returns a list of standard transactions.
3. Each row gets a type (pos / qpay / transfer / fee) and a normalised merchant name.
4. Rows are inserted; rows whose `(account, bank_ref)` already exist are skipped (overlapping statements are safe).
5. Auto-classifier applies rules, then merchant defaults.
6. Classify page lists every **merchant that is still unclassified**, grouped, with count and total — you pick a category once and tick “remember” to create a rule for next time.
7. Reports page: monthly income vs expense, spend by category, top merchants.

**Folder layout**

```

```

**Database schema**

| Table | Key columns | Notes |
| --- | --- | --- |
| banks | id, code UNIQUE, name | `xac` seeded |
| accounts | id, bank\_id, account\_number, holder, currency, is\_own | UNIQUE(bank\_id, account\_number); your accounts get is\_own = true |
| own\_account\_numbers | number UNIQUE | Your other account numbers, used to detect internal transfers |
| categories | id, name, kind (income/expense/transfer), is\_default, is\_active | UNIQUE(name, kind); never hard-delete, only deactivate |
| merchants | id, name UNIQUE, txn\_type, default\_category\_id | One row per normalised merchant/counterparty |
| rules | id, field (merchant/description/counterparty), match (exact/contains/startswith/regex), pattern, direction (in/out/any), category\_id, priority | Lower priority number runs first |
| imports | id, account\_id, file\_name, file\_sha256 UNIQUE, period\_start, period\_end, opening\_balance, closing\_balance, rows\_read, rows\_inserted, imported\_at | One per uploaded file |
| transactions | id, account\_id, import\_id, txn\_date, description, counterparty, bank\_ref, amount NUMERIC(14,2), balance, txn\_type, merchant\_id, category\_id, classified\_by (rule/merchant/manual), note | UNIQUE(account\_id, bank\_ref); amount is **signed**: + income, − expense |

## Classification

Every transaction is classified in this order, and the first hit wins: **manual choice** (never overwritten) → **rules** by priority → **merchant default category** → left unclassified for the review screen. Re-running the classifier only touches rows that are unclassified or were classified by a rule/merchant.

**Categories.** Your defaults are seeded, plus three I recommend adding because the statement needs them:

- Income: Self-earned, Gift, Donation, *Other Income* (added)
- Expense: Housing, Utilities, Restaurant, Groceries, Transportation, Healthcare & Medical, Debt Payments, Personal Care & Grooming, Family & Pet Care, Entertainment & Recreation, Clothing & Apparel, Savings & Investments, Gifts & Donations, Miscellaneous, *Bank Fees* (added — the 50₮/200₮ fees add up noticeably over a month)
- Transfer: *Internal Transfer* (added — money moved between your own accounts must not count as income or expense)

You can add, rename or deactivate categories on the Categories & Rules page.

**Seed rules from your sample statement.** These are loaded by `seed.py`. “Sure” ones are safe; “Guess” ones are my reading of the merchant name — delete or change any that are wrong before running the seed.
